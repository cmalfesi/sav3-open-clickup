# Release 11 · 0.9.2

Dashboard cards now keep actions in a contextual ⋯ menu. Desktop hover, keyboard focus and an open menu reveal controls; mobile/coarse-pointer layouts keep them visible. The menu includes refresh, expand, settings, duplication, keyboard reordering and removal, gated by existing dashboard permissions. Changes still require an explicit dashboard save and can be discarded. Per-card timestamps move into the menu. The toolbar uses compact desktop controls and larger touch targets.

A nullable, validated background color defaults to the current theme for old cards. Custom surfaces set local contrast tokens; chart color remains independent. Duplication copies nested filters and settings, gives the copy a new ID and places it below existing cards. No database migration is needed.

Space/Folder/List menu triggers now remain measurable when hover leaves the row, instead of switching to display:none as Radix moves focus to the portal. This prevents the anchor rectangle collapsing to the page origin. Open menus and keyboard focus retain the trigger; viewport collision handling remains active.

Validation: 96 unit/D1 tests, TypeScript and production build. Changed-file lint has zero errors. Real components were bundled into an isolated local fixture with synthetic data and a mock API: desktop cards/menu, duplication, custom background, draft save, keyboard opening/Escape/focus return, and Space menu anchoring were exercised. Responsive review used a 390px iframe, not a physical touch device. No production task data was changed during UI QA; an authenticated production browser check remains pending.
